## Change the boundary, not the host

The Host registers POST /crosery/dsh-drop/resolve (stat-only path matching, for a file or a folder), POST /crosery/dsh-drop/stage (bounded streaming upload; with a batch id, one file of a folder copy) and POST /crosery/dsh-drop/batch (folder copies: `limits`, `begin`, `commit`, `abort`). The browser owns a per-session AttachedFiles list (entries are `pending` until their path is acquired, then `ready`; a path is staged once per session), a page-local PreviewStore keyed per attachment, and a RailRegistry. The rail occupies the single conversation.input.attachments slot at priority -1; removing it restores the shipped occupant. It must own image intake as well as file intake, and it renders every composer draft by kind — images, and from 0.1.3 file drafts with their upload progress, failure and retry.

**Routing.** The page can hold several composers (0.1.7's subagent sidebar mounts a second one). Each mounted rail registers itself by identity and leaves by identity; nothing reads a "current session" (0.1.7 removed `sessions.list.getSnapshot().current`). A drop or paste goes to the rail whose `[data-composer-card]` contains the event target, otherwise to the latest rail with a session whose seat reports `canAcceptDrop`. A refusing composer shows the overlay's blocked face and answers the drop with a notice; with no composer at all the notice is a toast.

**Acquisition.** A non-image file takes the first rung that works: the desktop bridge `globalThis.__DSH_HOST_PATHS__.pathFor(file)` (feature-detected, read during the event; `''` means not disk-backed) is referenced in place; a `text/uri-list` hint is confirmed by the resolve route; otherwise the bytes are staged. Requests are document-relative (`crosery/dsh-drop/…`): the desktop page is `dsh-app://app/` and its forwarder carries the Host's auth cookie. A path upstream `formatFileMention` would refuse (a `"` or a C0/C1 control) is never referenced; it is copied under a safe name.

Keep transfer planning, filename reduction, mention spelling, send decisions and routing in DOM-free helpers (`contract.ts`, `client/send-plan.ts`, `client/registry.ts`, `client/composer-face.ts`). The client reads the seat's props structurally (see DropRail: owner verbs, the attachment union and the upload shape are restated, because they changed across trains) and reaches `sessions` and `conversation` by name. The rail's glyphs are inline SVG: the primitives module renamed its icons between trains, and the browser bundle must not require it.

**Sending.** Capture-phase submission is a compatibility seam, not a new sending implementation, and it has two shapes. On the 0.1.0–0.1.1 textarea composer the guard rewrites the draft with `setDraft`, submits through `inputActions.submit`, and clears. On the 0.1.2+ Lexical composer it appends `"\n\n" + one mention per line` at the document end — through `inputActions.insertText` with `captureInsertion()`'s revision on 0.1.7, the scoped `slash/input-insert-text` event on 0.1.2–0.1.6, or a whole-draft rewrite only when the draft holds no reference chip — and lets the composer's own Enter or Send handler submit. The end offset is in detect coordinates (`draft.length − Σ occurrence.length + occurrences.length`). One macrotask later it looks: a cleared draft or a transaction phase means sent, and only then are the staged entries cleared; otherwise the block is taken back out. Alt, AltGraph and Ctrl+Meta with Enter are sends up to 0.1.7-rc.1 and swallowed from 0.1.7-rc.2 without preventing the browser's Enter, which would type a line break after the block and read as sent; for those keys the guard appends and prevents only the default, so the composer's handler still runs. The Send and Stop controls are told apart by structure (the card's last button; a `path` arrow versus a `rect` square), never by hashed class names. A disabled Send (empty draft, only staged files) dispatches no click, so its `pointerdown` submits through the action face — only while idle, where that face's fixed queue mode equals the control's own. Test Enter, IME, Shift+Enter, Cmd/Ctrl+Enter, Alt/AltGraph/Ctrl+Meta+Enter, completion menus, Stop, disabled/read-only controls, pending staged files, refusal and file-only submission when changing it.

## State and lifecycle

Paths stay outside the draft until submission; user text precedes mentions so titles remain readable. Native PNG/JPEG/WebP/GIF go through the seat's own file intake (`onAddFiles`, or `onAddImages` on 0.1.1), minus files the seat already holds (same name, size and mtime), and the host's existing validation. Pending non-image references and preview bytes are page-local: refresh or unload loses unsent entries. A send the composer refuses leaves the entries staged; a send that fails after acceptance is restored by the composer with the mentions in its text, so the entries are not re-staged.

Paste takes the files and keeps genuine text: `text/plain` is dropped only when it merely restates the pasted file names (a Finder or Explorer copy); otherwise it is inserted over the selection (`inputActions.insertText` on 0.1.7, the browser's text insertion before). A paste aimed at some other plugin's field is left alone.

**Folders.** `planDrop` carries each dropped folder as `folders` (its `webkitGetAsEntry()` entry and the bridge path of its `getAsFile()` File, both read synchronously in the handler). A folder is ONE `AttachedFile` of kind `'directory'`, sent as ONE `mentionFor(path, 'directory')` — trailing slash, closed quote when spaced — and images inside it never reach the native image intake. The ladder (`client/folder-acquire.ts`): a bridge path is referenced in place at once and only counted for the card (default ignore list, capped at the default file ceiling); otherwise the page asks the batch route for its `limits`, walks the entry tree under them (`folder.ts`: loops `readEntries` until an empty batch, skips ignored names unopened, counts unreadable entries, stops at the first limit, and at a visit bound for trees of empty directories), tries a `file://` hint on the resolve route with the first eight files as its evidence, and otherwise refuses an over-limit folder whole or uploads it into a batch four files at a time and commits. The card is `pending` with files-done progress meanwhile, and the send guard holds any send while an entry is pending. Removing the card aborts the upload and sends `abort`; the Host's idle sweep catches an abort that never arrives. Each part of a mixed drop is handled on its own, so one bad folder does not reject its neighbours (upstream rejects the whole batch).

Keep state in apply/effect scope. Abort uploads and remove document listeners at disposal; open folder batches are removed when the Web server scope goes. An attachment's object URL is revoked and its bytes dropped when it leaves the rail (sent or removed), and every remaining one at plugin disposal. Text previews decode at most 64 KiB. Office and archives have identity cards, not document renderers.

## Security and storage

Uploaded names collapse to one path segment with UTF-8 byte budgets (C0/C1 controls and `"` stripped), then receive collision suffixes. Completed temporary files publish through an atomic no-replace hard link; concurrent drops must not change an earlier returned path.

A folder copy is a batch. `begin` creates `drops/DAY/.batch-<uuid>/` (a `tree/` being assembled and a `parts/` for bytes still streaming) and returns a random id, which is the capability for that directory alone, plus the limits frozen for the batch; at most eight are open, and one idle for 30 minutes is removed. Every file's relative path is re-sanitized on the Host by `safeRelativeSegments` — never trusted: `.`/`..` segments refuse the path, a leading root or drive is dropped, C0/C1 controls are stripped, Windows reserved characters, device names and trailing dots/spaces are replaced on win32, and each segment keeps the file-name budget within 1024 bytes in total — then joined under `tree/`, re-checked with `insideRoot`, and published by the same no-replace hard link (names that sanitize alike get suffixes). The per-file `maxBytes` and the folder's `folderMaxFiles`, `folderMaxBytes` and `folderMaxDepth` are enforced on the bytes that arrive, counting uploads in flight; crossing one answers 413 with the limit and removes the whole batch. `commit` claims the final name with an exclusive `mkdir` and renames `tree/` onto that empty claim (on Windows the claim is removed first), trying `name-2`, `name-3`… on collision, so a reader never sees a partial folder; a batch with no files is refused. `abort`, the idle sweep and disposal `rm -r` the batch directory, and an upload that raced an abort removes whatever it recreated. Copies of secrets such as `.env` are made like any other file; only the ignore list is skipped. Empty subdirectories are not recreated.

A folder claim on the resolve route carries up to eight files (relative path, size, mtime) instead of a size and mtime. Each must be a distinct file — by device and inode from `lstat`, because on a case- or normalization-insensitive volume `readme.md` and `README.md` are one file — `safeRelativeSegments`-clean, an `lstat` regular file whose real path lies inside the directory's real path, and match within 2 s; the sample must be as large as the folder allows (`min(8, files)`), and an empty sample needs a directory holding only ignored names. Only then is the folder counted — breadth-first `readdir`, links counted but never followed, ignored names counted unopened, bounded by 50 000 entries, 2 s and the depth ceiling, `truncated` when a bound hit — and the answer is counts, never names. A folder referenced in place is the real directory: the model can list `.git` there.

All three routes first ask the Host's admission check, read per request with `ctx.get('connection')?.requestRejection(req)`: from 0.1.2 (the service appears in 0.1.2-alpha.2) that is the harness's Host/Origin fence plus login-cookie authentication, and an unauthenticated caller gets 401 before anything is read or written. 0.1.0 and 0.1.1 publish the service without a check, and admit. While no `connection` service is up — its async `apply` still pending at boot, a restart after a config edit, a failed activation — every train answers 503 instead of admitting: on 0.1.2 and later that is exactly when the harness's own `/api` is closed, and on 0.1.0–0.1.1 the service is up whenever the Web server is. Then the CSRF gates: stage requires a non-safelisted header (the name header, or the batch header for a folder file), resolve and batch require an `application/json` body, all reject cross-origin Fetch Metadata (an absent header is admitted — the desktop forwarder strips it), and no CORS permission is granted. On 0.1.0–0.1.1 that is CSRF hardening, not authentication: keep DSH loopback-only or behind authenticated access; same-origin plugins and trusted local clients retain host authority.

Never navigate dropped blob URLs in a new tab: SVG is safe in an image element but not as a top-level document. HTML/XML render as escaped text. PDF blobs always use application/pdf even when the browser declares HTML. Browser codec/PDF support is not guaranteed. No file is automatically executed or extracted. Retention prunes date-named directories under DSH_HOME/drops, including anything manually placed inside them.

## Test the change

Use npm run typecheck, npm test, npm run build, npm run check and npm run check:dist. Host tests use real node:http servers and temporary directories; the send guard is exercised over a small document model in `tests/submit-flow.test.ts`. Keep client and host TypeScript programs separate; tests may include DOM types without importing host/client Context augmentations together. New runtime behavior needs a regression that fails on the previous behavior. For UI changes, verify a refreshed existing DSH URL with synthetic files: pure images, mixed batch, paste, removal, text/PDF preview, lightbox keyboard focus, narrow rail and file-only Enter; for folders, a real folder dropped through CDP `Input.dispatchDragEvent` (`data.files` takes a directory path), a stubbed `__DSH_HOST_PATHS__`, an over-limit folder, and removal mid-upload under `Network.emulateNetworkConditions`. Do not send real documents or expose session history in screenshots. Record what actually ran; old README claims are not evidence.

Any client change must typecheck and pass the tests against every published train, not just the pinned one: `node scripts/sweep-trains.mjs` copies the tree once per train, puts it on that exact version with the same `scripts/harness-target.mjs --repoint --install` a CI cell runs, and runs typecheck, the bundle's seed-member check (`check-dist.mjs --bundle-only`) and tests (see docs/harness-compatibility.md). A change to the Host routes, the manifest or the bundle also runs `node scripts/smoke-boot.mjs --dsh <version>`: it installs the packed plugin with `dsh plugin add` into a throwaway home, boots `dsh --profile web`, and checks activation, the three routes (401 without the login cookie from 0.1.2, a real stage and resolve), and the served bundle against the shell's module table and the train's exports. `lib/` is committed, so run npm run build and commit the regenerated dist with the source change — check:dist fails otherwise.
