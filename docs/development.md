## Change the boundary, not the host

The Host registers POST /crosery/dsh-drop/resolve (stat-only path matching) and POST /crosery/dsh-drop/stage (bounded streaming upload). The browser owns a per-session AttachedFiles list (entries are `pending` until their path is acquired, then `ready`; a path is staged once per session), a page-local PreviewStore keyed per attachment, and a RailRegistry. The rail occupies the single conversation.input.attachments slot at priority -1; removing it restores the shipped occupant. It must own image intake as well as file intake, and it renders every composer draft by kind — images, and from 0.1.3 file drafts with their upload progress, failure and retry.

**Routing.** The page can hold several composers (0.1.7's subagent sidebar mounts a second one). Each mounted rail registers itself by identity and leaves by identity; nothing reads a "current session" (0.1.7 removed `sessions.list.getSnapshot().current`). A drop or paste goes to the rail whose `[data-composer-card]` contains the event target, otherwise to the latest rail with a session whose seat reports `canAcceptDrop`. A refusing composer shows the overlay's blocked face and answers the drop with a notice; with no composer at all the notice is a toast.

**Acquisition.** A non-image file takes the first rung that works: the desktop bridge `globalThis.__DSH_HOST_PATHS__.pathFor(file)` (feature-detected, read during the event; `''` means not disk-backed) is referenced in place; a `text/uri-list` hint is confirmed by the resolve route; otherwise the bytes are staged. Requests are document-relative (`crosery/dsh-drop/…`): the desktop page is `dsh-app://app/` and its forwarder carries the Host's auth cookie. A path upstream `formatFileMention` would refuse (a `"` or a C0/C1 control) is never referenced; it is copied under a safe name.

Keep transfer planning, filename reduction, mention spelling, send decisions and routing in DOM-free helpers (`contract.ts`, `client/send-plan.ts`, `client/registry.ts`, `client/composer-face.ts`). The client reads the seat's props structurally (see DropRail: owner verbs, the attachment union and the upload shape are restated, because they changed across trains) and reaches `sessions` and `conversation` by name. The rail's glyphs are inline SVG: the primitives module renamed its icons between trains, and the browser bundle must not require it.

**Sending.** Capture-phase submission is a compatibility seam, not a new sending implementation, and it has two shapes. On the 0.1.0–0.1.1 textarea composer the guard rewrites the draft with `setDraft`, submits through `inputActions.submit`, and clears. On the 0.1.2+ Lexical composer it appends `"\n\n" + one mention per line` at the document end — through `inputActions.insertText` with `captureInsertion()`'s revision on 0.1.7, the scoped `slash/input-insert-text` event on 0.1.2–0.1.6, or a whole-draft rewrite only when the draft holds no reference chip — and lets the composer's own Enter or Send handler submit. The end offset is in detect coordinates (`draft.length − Σ occurrence.length + occurrences.length`). One macrotask later it looks: a cleared draft or a transaction phase means sent, and only then are the staged entries cleared; otherwise the block is taken back out. The Send and Stop controls are told apart by structure (the card's last button; a `path` arrow versus a `rect` square), never by hashed class names. A disabled Send (empty draft, only staged files) dispatches no click, so its `pointerdown` submits through the action face — only while idle, where that face's fixed queue mode equals the control's own. Test Enter, IME, Shift+Enter, Cmd/Ctrl+Enter, completion menus, Stop, disabled/read-only controls, pending staged files, refusal and file-only submission when changing it.

## State and lifecycle

Paths stay outside the draft until submission; user text precedes mentions so titles remain readable. Native PNG/JPEG/WebP/GIF go through the seat's own file intake (`onAddFiles`, or `onAddImages` on 0.1.1), minus files the seat already holds (same name, size and mtime), and the host's existing validation. Pending non-image references and preview bytes are page-local: refresh or unload loses unsent entries. A send the composer refuses leaves the entries staged; a send that fails after acceptance is restored by the composer with the mentions in its text, so the entries are not re-staged.

Paste takes the files and keeps genuine text: `text/plain` is dropped only when it merely restates the pasted file names (a Finder or Explorer copy); otherwise it is inserted over the selection (`inputActions.insertText` on 0.1.7, the browser's text insertion before). A paste aimed at some other plugin's field is left alone.

Folders are carried through `planDrop` as `folders` (entry and bridge path included) and reported as skipped; `AttachedFile.kind` already has `'directory'` and `mentionFor(path, 'directory')` the trailing-slash spelling, for the folder stage.

Keep state in apply/effect scope. Abort uploads and remove document listeners at disposal. An attachment's object URL is revoked and its bytes dropped when it leaves the rail (sent or removed), and every remaining one at plugin disposal. Text previews decode at most 64 KiB. Office and archives have identity cards, not document renderers.

## Security and storage

Uploaded names collapse to one path segment with UTF-8 byte budgets (C0/C1 controls and `"` stripped), then receive collision suffixes. Completed temporary files publish through an atomic no-replace hard link; concurrent drops must not change an earlier returned path.

Both routes first ask the Host's admission check, read per request with `ctx.get('connection')?.requestRejection(req)`: on 0.1.7 that is the harness's Host/Origin fence plus login-cookie authentication, and an unauthenticated caller gets 401 before anything is read or written. Earlier trains have no such service, and the check admits everything. Then the CSRF gates: stage requires the non-safelisted name header, resolve requires an `application/json` body, both reject cross-origin Fetch Metadata (an absent header is admitted — the desktop forwarder strips it), and no CORS permission is granted. On pre-0.1.7 trains that is CSRF hardening, not authentication: keep DSH loopback-only or behind authenticated access; same-origin plugins and trusted local clients retain host authority.

Never navigate dropped blob URLs in a new tab: SVG is safe in an image element but not as a top-level document. HTML/XML render as escaped text. PDF blobs always use application/pdf even when the browser declares HTML. Browser codec/PDF support is not guaranteed. No file is automatically executed or extracted. Retention prunes date-named directories under DSH_HOME/drops, including anything manually placed inside them.

## Test the change

Use npm run typecheck, npm test, npm run build, npm run check and npm run check:dist. Host tests use real node:http servers and temporary directories; the send guard is exercised over a small document model in `tests/submit-flow.test.ts`. Keep client and host TypeScript programs separate; tests may include DOM types without importing host/client Context augmentations together. New runtime behavior needs a regression that fails on the previous behavior. For UI changes, verify a refreshed existing DSH URL with synthetic files: pure images, mixed batch, paste, removal, text/PDF preview, lightbox keyboard focus, narrow rail and file-only Enter. Do not send real documents or expose session history in screenshots. Record what actually ran; old README claims are not evidence.

Any client change must typecheck and pass the tests against every published train, not just the pinned one: `node scripts/sweep-trains.mjs` copies the tree once per train, repoints the `@deepseek-ai/dsh-*` devDependencies at that exact version, and runs typecheck and tests (see docs/harness-compatibility.md). `lib/` is committed, so run npm run build and commit the regenerated dist with the source change — check:dist fails otherwise.
